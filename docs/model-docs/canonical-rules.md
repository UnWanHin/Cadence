# Cadence 模型权威规则（平台对齐基线）

> 本文件把 仓库根目录 `src/` 中**已经实现并可测试**的动作评估规则固定下来，作为 `need/`、`ui/`、`database/` 三个模块的共同口径。
>
> 权威顺序：`src/cadence/*`（C++ 核心）> `prototype/pose-prototype.html`（浏览器参考实现）> 本文档的解释文字。
> 当 C++ 核心与浏览器原型出现差异时，以 C++ 核心为准；浏览器原型只作为交互和展示参考。

## 1. 输入与关键点

- 输入为 MediaPipe Pose 的 33 个归一化关键点：`x, y, z, visibility`。
- 任何参与计算的关键点，其 `visibility` 必须 **≥ 0.50**；否则该角度/距离视为不可用，不得用旧帧续算。
- 关节角度使用三维向量计算；腕距使用二维平面距离 `hypot(x1-x2, y1-y2)`。
- 关键点索引：

| 名称 | 索引 | 名称 | 索引 |
|---|---:|---|---:|
| 左肩 | 11 | 右肩 | 12 |
| 左肘 | 13 | 右肘 | 14 |
| 左腕 | 15 | 右腕 | 16 |
| 左髋 | 23 | 右髋 | 24 |
| 左膝 | 25 | 右膝 | 26 |
| 左踝 | 27 | 右踝 | 28 |

## 2. 特征定义（`pose_features.cpp`）

| 特征 | 计算 | 说明 |
|---|---|---|
| `leftKnee` | `angle(左髋 23, 左膝 25, 左踝 27)` | 左膝角 |
| `rightKnee` | `angle(右髋 24, 右膝 26, 右踝 28)` | 右膝角 |
| `knee` | `min(leftKnee, rightKnee)` | 主膝角 |
| `leftElbow` | `angle(左肩 11, 左肘 13, 左腕 15)` | 左肘角 |
| `rightElbow` | `angle(右肩 12, 右肘 14, 右腕 16)` | 右肘角 |
| `elbow` | `min(leftElbow, rightElbow)` | 主肘角 |
| `hip` | `angle(左肩 11, 左髋 23, 左膝 25)` | 躯干直线度；C++ 核心取左侧 |
| `wristDistance` | `distance(左腕 15, 右腕 16)` | 开合跳腕距 |

> 拍摄要求：为了让 `hip` 稳定可用，首版要求**左侧身体朝向镜头**，并保证肩、髋、膝、踝可见。浏览器原型中的 `min(leftHip, rightHip)` 是参考实现的兼容写法，不作为平台权威口径。

## 3. 动作与判定表

`wasm_api.cpp` 的整数编号固定为：`0=深蹲`、`1=俯卧撑`、`2=弓步蹲`、`3=平板支撑`、`4=开合跳`。

| 编号 | 代码 | 名称 | 类型 | 必需特征 | 目标条件 | 质量分 `q` | 单次积分 | 卡路里 |
|---:|---|---|---|---|---|---|---|---|
| 0 | `squat` | 深蹲 | 计数 | `knee` | `knee <= 90°` | 基础 1.0；左右膝差 `>20°` 或 `hip < 60°` 时降为 0.7 | `floor(10 × q)` / 次 | 0.6 / 次 |
| 1 | `pushup` | 俯卧撑 | 计数 | `elbow` | `elbow <= 90°` | 基础 1.0；`hip < 150°` 或 `hip > 200°` 时降为 0.7 | `floor(10 × q)` / 次 | 0.5 / 次 |
| 2 | `lunge` | 弓步蹲 | 计数 | `knee` | `knee <= 90°` | 基础 1.0；左右膝差 `>20°` 或 `hip < 60°` 时降为 0.7 | `floor(10 × q)` / 次 | 0.7 / 次 |
| 3 | `plank` | 平板支撑 | 保持 | `hip` | 无“到位/回位”，按直线度评分 | `max(0, 1 - abs(hip - 180) / 60)` | `floor(elapsedSeconds × 0.15 × 10)` | 0.15 / 秒 |
| 4 | `jumpingjack` | 开合跳 | 计数 | `wristDistance` | `wristDistance >= 0.70` | 目标内 1.0，否则 0.7 | `floor(10 × q)` / 次 | 0.4 / 次 |

### 3.1 纠错提示（C++ 核心）

- 深蹲/弓步蹲：左右膝差 `>20°` → “左右膝屈度不一致，调整重心”；`hip < 60°` → “躯干前倾过多，注意挺胸”。
- 俯卧撑：`hip < 150°` 或 `hip > 200°` → “保持身体直线，避免塌腰或翘臀”。
- 平板支撑：`q < 0.65` → “保持身体直线，收紧核心”。

## 4. 计数状态机（`repetition_counter.cpp`）

对计数型动作，先把主特征映射为 `progress ∈ [0, 1]`：

- 平板支撑：`progress = q`（只用于展示，不计数）。
- 开合跳：`progress = wristDistance >= 0.70 ? 1 : 0`。
- 深蹲/弓步蹲/俯卧撑：
  - `main <= 90` → `1`
  - `main >= 160` → `0`
  - 其他 → `(160 - main) / 70`

状态机：

- 进入目标：`progress >= 0.75`，状态变为“到位”，**不计数**。
- 离开目标：`progress <= 0.55`，完成 1 次，计数 +1。
- 只有“进入后再离开”才算一次；直接开始于目标内不计数。
- 没有 2 秒稳定期，也没有“有效帧数 ÷ 帧率”的换算。

## 5. 会话汇总（`workout_session.cpp`）

`SessionSummary` 的固定字段：

```json
{
  "repetitions": 0,
  "points": 0,
  "calories": 0.0,
  "averageQuality": 0.0,
  "elapsedSeconds": 0.0
}
```

- `repetitions`：计数型动作的完成次数；平板支撑为 0。
- `points`：计数型动作在每次完成时累加 `floor(10 × q)`；平板支撑每帧按 `floor(elapsedSeconds × 1.5)` 重算。
- `calories`：计数型按次累加固定值；平板支撑按秒累加 `0.15 × elapsedSeconds`。
- `averageQuality`：所有“检测到姿态”的帧的质量分均值；平板支撑同样参与均值。
- `elapsedSeconds`：调用方传入的单调递增运动时长；平板支撑的积分依赖该值。

## 6. 平台级规则（不属于模型，但接入时必须遵守）

以下规则由服务端/前端会话层实现，模型本身不负责：

- 采集层要求单人入镜；多人或无人时状态为“无法判断”，不更新计数。
- 开始前 3 秒准备倒计时；倒计时不计入运动时长。
- 单次自然时长上限 20 分钟，达到后自动结束。
- 每日积分上限暂定 **600 分**（按模型 10 分/次约等于 60 次；可由规则配置调整）。结算时 `actual = min(points, max(0, 600 - 当日已入账))`。
- 会话归属日按 Asia/Shanghai 零点；周榜为周一 00:00 至下周一 00:00。
- 周榜只统计已结算、未删除、账本有效且自愿公开的用户；同分名次 1、1、3。

## 7. 与浏览器原型的已知差异

浏览器原型 `prototype/pose-prototype.html` 是交互参考，和 C++ 核心存在以下差异；平台实现以 C++ 核心为准：

| 项目 | C++ 核心 | 浏览器原型 |
|---|---|---|
| 髋角 | 左侧肩-髋-膝 | 左右两侧取较小值 |
| 单次积分取整 | `floor`（`static_cast<int>`） | `Math.round` |
| 计数型质量分 | 规则命中为 1.0 或 0.7 | 按到位程度和问题数量连续计算 |
| 平板积分 | `floor(elapsed × 1.5)` | 按帧累加后 `round` |
| 会话时长 | 调用方传入 | 页面 `performance.now()` |

平台接入时，若需要浏览器与 C++ 完全一致，应以本文第 3—5 节重写浏览器评估层，或直接编译 `cadence_wasm` 并通过 `cadence-wasm-bridge.js` 调用 C++。

## 8. 与旧需求的差异

旧版 `need/` 与 `ui/` 以“平板支撑、靠墙静蹲两种静态动作 + 有效时长换积分”为基线；该基线**不再使用**。平台现在以本文件的五种动作、计数状态机和模型积分公式为准。旧版中的“有效时长”保留为展示/统计字段“有效运动时长”，但**不再参与积分计算**（平板支撑除外，其积分使用模型 `elapsedSeconds`）。
